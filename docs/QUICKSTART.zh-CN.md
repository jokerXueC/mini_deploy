# mini_deploy 快速上手

首次安装或某项功能还不会开启，先读[完整安装与功能使用指南](../ui/user-guide.md)：包含所有主要功能的准备条件、操作步骤、可复制命令、成功标准与排查方法。安装后可从面板顶部文档图标或「功能检查」直接打开、搜索和下载，本机命令按实际安装路径生成。

mini_deploy 是轻量的服务器运维与请求监控面板，名称保持不变。保留服务器监控、Docker 容器与镜像管理、Nginx/证书、请求采集和独立网关；不再提供 Git 部署、脚本执行、WebHook 自动发布或业务运行环境生成。

> [!WARNING]
> 当前为公开测试前版本，默认安装器以 root 运行 Agent，权限拆分及完整恢复/版本回滚尚未完成。请使用受控的专用 Linux 测试服务器。

## 安装与登录

需要 Linux、root/sudo、systemd、Python 3.10+，以及用于下载面板自身的 Git。不需要业务仓库、Deploy Key 或部署脚本。Docker 和 Nginx 按需使用。缺少基础依赖时先执行完整指南中对应系统的安装步骤；已有代理无需重复安装。

```bash
mini_deploy_source="$(mktemp -d /tmp/mini-deploy-source.XXXXXX)" && git clone --depth 1 --branch main https://github.com/jokerXueC/mini_deploy.git "$mini_deploy_source" && SETUP_NGINX=no SETUP_HTTPS=no bash "$mini_deploy_source/install.sh"
```

安装时选择语言并设置管理员密码。随后打开 `http://服务器公网IP:6868`，使用该密码登录。面板固定监听 `0.0.0.0:6868`，无需域名或证书。云安全组需允许 TCP 6868，建议限制访问来源；提交私钥等敏感信息前使用 HTTPS 或 SSH 隧道。上面的命令先提供 IP 访问；后续创建面板域名入口需按完整指南设置 `DEPLOY_DOMAIN`、`SETUP_NGINX=yes` 和 `SETUP_HTTPS=yes`，先核对 80/443 未被其他代理占用。

Docker 可选，用于容器管理、Docker Nginx 和独立请求网关。安装器默认 `SETUP_DOCKER=ask`：交互时询问，默认回答“否”，无终端时跳过，不自动选择“是”。无需 Docker Compose 或 PyYAML。仅查看已有 Caddy 请求日志时，无需再安装 Nginx。

### 先确认你需要哪些能力

| 目标 | 面板会处理 | 需要你准备 |
| --- | --- | --- |
| 整机资源与性能历史 | 后台采样、保存和刷新，持久化失败时显示原因 | 支持的 Linux/systemd 环境、可写且有容量的数据磁盘 |
| Docker 管理 | 识别本机容器、资源及日志 | 本机 Docker；无需为面板再启动一套业务环境 |
| 网站请求历史 | 检测现有 Nginx/Caddy，预览改动，确认后接入并验证采集 | 已运行的网站和代理；未经过代理的服务需另建入口 |
| 域名与证书 | 发现网站与证书，支持受控配置和续期 | 域名 DNS、云安全组、公网端口及必要的 DNS 服务商凭据 |
| SSH / AI | SSH 会话、模型配置、授权和诊断工具 | 目标主机账号、网络连通；AI 模型地址、密钥和工具授权 |
| 基础防护 | 支持范围内的登录策略、封禁与流量规则 | 服务器防火墙依赖及受支持入口；不能替代云端 DDoS 清洗 |

有 Caddy 就继续使用 Caddy，有 Nginx 就继续使用 Nginx，不需要为了请求监控更换代理。自动接入仅修改已确认的规则，复杂配置无法可靠处理时明确提示，并提供查询和填写步骤。普通日志预览与持久请求历史不同：要跨重启查询和导出完整已采集历史，请启用请求网关。

### 安装后怎样验收

安装器在启动后等待最多约 30 秒，核对 `/health` 返回的运行版本与安装的 `agent.py` 一致，并再次确认 systemd 服务保持 active；可选组件处理完还会复验。健康失败、旧版本仍占端口或返回异常时以失败退出，打印实际服务与诊断命令，不再输出安装完成。这只验收面板服务，不证明外网可达或可选功能已经启用；失败时尚不具备安装器完整自动回滚能力。

登录后打开顶部「功能检查」（也可访问 `/ui?view=setup`）：查看基础运行和按需功能，每项都有配置入口及验收步骤。检查复用后台采样和已保存配置，性能与请求历史使用只读数据库核验；不会额外连接模型、登录 SSH、发送通知或应用防火墙。页面可见时每 15 秒复查，离开或切到后台后停止。模型已保存、SSH 依赖可用、采集游标推进都不会直接显示为整条链路已核验；业务低流量也不直接视为接入故障。检查失败时会保留上次结果并明确提示失败，避免把旧状态当成本次成功。

登录后确认整机数值持续更新，再打开性能历史，等待采样后检查时间向前推进。已有容器应能看到实际名称、状态和日志。网站请求接入后，使用原域名访问对应路径，确认「已收到真实请求并写入历史」；网关运行中或配置已接入都不能单独证明完整链路正确。具体兼容范围、状态含义及无法自动处理时的步骤见[请求网关说明](REQUEST_GATEWAY.zh-CN.md)。

安装器不会自动修改云安全组、DNS、CDN 或业务发布模板。若公网打不开，先在服务器运行 `curl -fsS http://127.0.0.1:6868/health`：本机正常再检查云安全组和入口代理；本机失败查看 `journalctl -u mini-deploy-agent -n 80 --no-pager -l`。自定义服务名请替换 unit 名称。

升级前请保留安装器生成并验证的备份。当前命令行安装器失败后的服务重启保护不等于程序和数据的完整自动回滚，不要把备份存在当作恢复已经完成；失败后需检查健康接口和日志。下文「排查与数据」说明备份位置和校验方式，完整配置与数据恢复仍需维护者核对；网页「恢复程序」仅恢复程序。

## 首次使用

「服务器状态 → 更多性能指标 → Swap」可一键开启 2 GiB Swap，重启后自动生效。仅支持 root 运行的 Linux 主机；新建交换文件支持 ext4/XFS，创建后需至少剩余 1 GiB 磁盘空间。面板创建的 Swap 关闭后保留交换文件，同时取消其开机启用；交换文件和 fstab 备份保存在 `/var/lib/mini-deploy-swap`，不纳入面板数据备份。

已有系统 Swap 可使用同一开关临时关闭、再次开启，不重复创建、不格式化、不删除原交换文件或设备，也不改原开机配置，重启后可能自动恢复。关闭前检查可用内存，内存不足时拒绝；多个来源关闭失败时尝试恢复已经停用的来源。恢复信息保存在数据目录的 `host-swap/external.json`，面板重启后仍可再次开启；路径或文件身份变化时拒绝自动操作。尚未启用且只有开机配置的系统 Swap 不自动接管。

1. 查看服务器 CPU、内存、磁盘和网络，确认数据持续更新。
2. 使用 Docker 时，查看容器状态、资源和日志；镜像页可列出、搜索、拉取及非强制删除镜像。拉取镜像不会自动更新业务容器。
3. 已有网站需要请求监控时，选择已有代理日志来源，或按[独立网关说明](REQUEST_GATEWAY.zh-CN.md)开启记录。
4. 打开「域名与证书」，直接查看自动发现的网站和证书，不用先填写代理类型、容器或证书路径。

无需先添加 Git 项目。业务服务应由你在面板外准备并运行，面板不生成业务 Compose、systemd 服务、构建命令或部署脚本。

## 排查服务器异常

「资源观测」默认显示最近 1 小时，CPU、内存和网络按同一时间轴排列。可切换到服务器整体或某个 Docker 容器，点击时间格查看该时段的平均值、峰值、已保存的进程现场和同时段事件；「定位峰值」直接选中当前指标的峰值时段。历史每约 30 秒刷新，实时模式仍可查看最近 60 秒。

缺失采样留空，现场过期或事件读取失败会明确提示，不使用当前进程推断过去的情况。整机 CPU 和内存使用实际采样峰值；容器历史及网络合计显示区间均值峰值。网络亮度只表示相对吞吐，不代表带宽饱和；容器历史没有关联进程现场时不推测进程归属。

服务器页点击「进程与端口」查看占用最高的进程和监听归属；进程 CPU 是存活期间的平均占用，100% 表示一个逻辑核。仅在打开或刷新时读取，结果缓存 10 秒，不持续扫描。

「查看日志」自动列出已发现的 Docker 容器、systemd 服务，以及 `/var/log/nginx`、`/var/log/caddy`、`/var/log/mini_deploy` 下的常见日志。选择来源后可筛选时间、级别和关键字，按需开启 5 秒自动刷新，或下载当前筛选结果。

异常中心展开记录，点击「排查异常」，查看保存的退出码、OOM、重启证据、同一次异常的时间线和仍保留的资源采样。「查看异常前后日志」默认取前后 5 分钟；容器已重建、日志已轮转、时间无法识别或读取达到上限时明确提示，不把缺失数据当作恢复。

排查均为只读，不删除、修改服务器文件或重启服务。「AI 运维诊断」直接读取面板所在服务器的异常、资源、进程现场和关联日志，无需建立 SSH 连接。已配置模型时，打开对话即发起所选范围的分析；后续可继续提问，记录保存在诊断历史中。问题和工具取得的证据会发送至已配置的模型接口。

### 让 AI 检查项目代码

在诊断对话的「代码范围」选择项目，例如 `/opt/aimore`，然后提问「只查看 AimOre 的 `/cloud/runtime/commands/claim` 及调用链，分析超时原因，不修改文件」。AI 可以浏览源码目录、搜索接口或函数、按行读取文件，并结合异常现场给出文件位置和依据，不需要手工粘贴源码。切换项目会开启新对话，原记录仍保留在历史中，防止不同项目的代码混入同一次分析。

项目列表自动识别 `/opt`、`/srv`、`/var/www`、`/root` 以及 `/home/<用户>` 下的常见项目，并结合已发现 Docker 容器的 Compose 工作目录和 bind 挂载定位宿主机源码。只扫描目录标记，不会在发现项目时读取全部文件；关联异常只能唯一匹配到一个项目时，会自动选中该项目。源码仅存在于 Docker 镜像内、没有宿主机源码目录时，本入口无法读取；宿主机源码也不一定等于镜像内或故障发生时的版本。

源码读取目前用于 Linux 服务器，后端限定在所选项目内，拒绝符号链接、硬链接、特殊文件、面板私有目录及常见凭据文件；不执行仓库脚本，也不提供写入工具。大目录需缩小搜索范围，结果可按文件或行号翻页，跳过和截断会明确标记。工具会隐藏常见密码、令牌和私钥格式，但不能保证识别所有业务自定义敏感内容，开放源码前应核对模型接口。更新此功能需运行新版 `install.sh`，以安装新增的源码读取模块。

## Docker 镜像加速

在「服务器状态 → Docker 镜像 → 镜像加速」打开配置，面板自动读取主机已有加速地址。新增、修改或移除后点击「保存并生效」，无需手写 JSON 或执行服务器指令。删除全部地址会恢复 Docker 默认拉取方式，不删除镜像、容器和业务文件。

只修改 `registry-mirrors`，保留 Docker 其他配置，应用前自动校验并备份。优先热加载，必要时重启 Docker；有运行中容器且没有开启 live-restore 时，不自动重启，应用失败会尝试恢复原配置。页面展示进度、结果和备份位置。

加速地址由你使用的服务商提供，填一次即可长期保留；主要用于 Docker Hub。配置生效后可点击「拉取 nginx:stable-alpine 验证」，镜像会保留但不会启动容器。拉取成功也可能是 Docker 回退到官方源，不代表一定经过加速器。

目前支持 Linux 主机上 root 权限、systemd 管理的本机 Docker；远程、自定义 Socket、rootless、容器内运行的面板，以及启动参数指定镜像地址等无法安全修改的情况，会显示原因。

## 远程终端

AI 默认不限制生成等待时间、分析总时长和工具调用轮数，支持流式显示及随时停止；完整回复会保存到对话历史。模型设置的「响应设置」可选填无响应等待时间和最大输出 tokens。OpenAI 兼容接口留空沿用服务默认；Claude 协议必须指定输出额度，留空使用 16384，可按模型支持范围调整。服务商自己的上下文、额度及超时仍由服务商决定。

打开「远程终端」，填写服务器 IP/主机名、SSH 端口（默认 22）、用户名和密码，或上传私钥。首次连接先核对主机指纹，确认后进入交互终端。目标服务器无需安装 mini_deploy，只需能被面板服务器通过 SSH 访问。

通过 HTTP 访问时，在「远程终端」上方勾选确认并点击「允许本次登录使用 HTTP」，即可使用 SSH 和模型功能；退出重登需再次确认。HTTP 到面板的凭据和终端内容为明文，建议使用 HTTPS 或本地 SSH 隧道。支持终端缩放、复制粘贴及移动端快捷键。仅保存连接名称与地址，不保存密码、私钥、口令或终端内容。详情见[SSH 使用说明](SSH.zh-CN.md)。

安装器自动尝试安装 `python3-paramiko`；安装失败只关闭 SSH 功能，其他页面继续使用。升级后旧登录需退出并重新登录，远程终端才会使用新的独立会话凭据。

「远程终端 → 模型设置」可配置 OpenAI 兼容服务或 Claude 原生接口，无需先连接 SSH。未连接时正常聊天；连接后选择「操作前确认」或「自动操作」。前者自动检查、操作前询问；后者一次授权后自动检查、编辑配置、管理服务，并执行规则识别的通用查询。HTTP 下先完成上述确认，模型服务的远程接口仍使用 HTTPS。详见 [AI 对话与权限](SSH.zh-CN.md)。

容器内查询、数据库统计等通过通用命令完成，不用再单独选择模式。自动模式下，无法判断影响的脚本或命令仍需确认；明确的删除、清空、格式化和卸载命令被阻止。规则不能保证识别所有间接删除行为，通用命令不自动备份或回滚。授权只对当前连接生效，最多 30 分钟；旧版自动授权需重新确认才会扩大范围。通用命令默认等待 60 秒，可指定最多 600 秒，输出最多保留 64 KiB；截断后仍等待退出码。停止或超时不保证远端进程终止。

使用旧更新器的安装需先运行一次 `install.sh`，修复将新增模块误判为兼容变化的问题。新版网页更新会按目标发布清单安装新增模块；真正的依赖、服务或数据约定变化仍需安装器，详见下文「面板维护」。

## 异常中心

1. 打开「异常中心」，查看服务器资源、容器、网站与接口的当前异常及恢复。容器自动识别，不需要填写编程语言或启动命令。异常历史每页最多 5 条，支持翻页；操作审计、正常启停和单独的知晓记录不在此展示。
2. 展开异常查看退出码、OOM、重启和健康检查证据；可以直接查看容器日志。点击「已知晓」后故障仍显示，暂停该次故障的重复提醒；真正恢复后记录恢复事件，新一轮故障重新提醒。
3. 需要检查业务是否能访问时，展开「网站与接口监测」，填网站或接口地址，例如 `https://example.com` 或 `http://192.168.1.10:8080/health`，点击「开始监测」。只填域名时默认 HTTPS。
4. 点击「设置通知」，开启企微、钉钉或邮箱中的一个，保存并发送测试。之后自动检查，无需调整 Nginx、Caddy、Docker 或业务代码。HTTPS 的线上证书也会出现在「域名与证书 → 线上持续监测」。

默认每 30 秒请求一次地址，2xx/3xx 视为可访问；不跟随重定向，耗时统计到响应头。异常持续 60 秒后提醒，相同问题每小时提醒一次，恢复后通知。响应超过 3 秒、证书剩余不超过 14 天也会提醒，可在「提醒规则」修改。正常证书每小时复查，失败时每 30 秒重试；「立即检查」也会复查证书。最多 50 个网址，同时最多 4 个检查任务，繁忙时可能延迟。

服务器 CPU、内存、磁盘使用率达到 90%，Docker 服务异常、容器不健康、重启循环或非零退出，也进入同一告警流程。手动停止的正常容器不会直接触发异常。数据过期或无法读取不等于恢复。所有检查从安装面板的服务器发起，不代表全球可用性；没有可用样本时不会发送恢复通知。

Docker 自动读取退出码、内存不足被杀标记、重启策略和健康检查结果；OOM 故障及近 5 分钟观测到至少 3 次新增重启立即提醒，其他容器异常沿用持续异常规则。初次读取的累计重启次数不直接算作重启风暴。Docker 事件流记录生命周期变化并在断线后重连，定时检查核对当前状态；Docker 自身回放有限，断线期间不能保证历史完整。没有 HEALTHCHECK 的容器不会被当作业务已健康；健康检查记录仅保存退出码与时间，不保存原始输出，可通过容器日志继续排查。

每轮容器检查限制执行时长，最多跟踪 256 个容器身份；检查不完整或同一 Compose 身份暂时出现多个容器时显示采样未知，已有故障保持待更新。重建后的 Compose 服务尽量按项目、服务和副本关联；没有 Compose 身份的容器按容器 ID 区分。面板主动操作单独记录，不自动重启故障服务。

「静音 1 小时」只暂停通知，仍持续监测。暂停/移除监测均不操作业务文件、服务或证书。提醒规则、故障、已知晓状态和静音保存在数据目录的 `website-monitoring.json`；事件历史最多保留 30 天、1000 条（先达到的限制生效）。升级沿用原数据，不重置历史；它不是每次探测的历史数据库。

线上证书检测适用于任意 HTTPS 服务；启用 CDN 时显示 CDN 边缘证书。检查源站需另填源站可访问的 HTTPS 地址。HTTP 地址不检查证书。仅做监测，不接管 Caddy/Certbot 续签，也不自动替换外部服务证书。

## 自动发现网站与证书

安装启动后在后台扫描，之后每 10 分钟更新，也可点击「重新扫描」。只检查本机服务配置、Docker 启动参数与已发现的证书挂载，以及 `/etc/letsencrypt/live`、Nginx/Caddy 常见证书目录，不遍历整盘或数据库。

首页统一展示有明确域名的网站、来源和到期时间。内部网关、默认站点收在「内部入口与默认站点」，未确认引用的证书收在「其他证书文件」，默认折叠。当前识别 Nginx/Caddy 配置，扫描不到的来源会提示，不代表服务器没有网站。每轮有 60 秒、40 个容器、200 个目录证书文件及 500 条结果的限制；超过限制会提示部分结果未确认。

「检查线上」访问域名标准 HTTP/HTTPS 端口，显示访问状态和线上证书，并与磁盘证书对比。CDN、非标准端口及未重载配置可能使两者不同。Caddy 自动管理目录里的匹配证书仅作为候选，不直接认定为正在提供的证书。

可可靠操作的 Nginx 证书直接显示「替换证书」：上传证书链和私钥即可，不用重新登记站点或填写路径。原来通过面板托管的证书也在这里替换，同时更新原有记录。系统校验共用证书的域名、备份原文件、测试配置并重载；失败时恢复原文件和记录。备份位于数据目录下的 `certificate-backups`。自动续签、符号链接、外部只读挂载、单文件挂载、共享关系不明确的证书不直接覆盖。扫描和替换都不删除原业务文件或重建容器。

已确认配置引用的有效运行站点证书会纳入到期提醒；旧文件、待确认记录和自动管理目录的候选证书不按在线证书告警。需要持续检查实际线上证书时，在「异常中心」展开网站检查并添加网址。


## 请求采集

「请求记录 → 导出」默认下载全部入口仍保留的历史，可改为当前入口或当前时间和筛选。分析包包含完整明细 `requests.csv`、地址汇总 `routes.csv`、时间趋势 `timeline.csv` 和离线图表 `report.html`，不受页面分页及每类 30 条明细限制；也可单独下载 CSV 或报告。CSV 使用 UTF-8，Excel 可直接打开，时间为 UTC。报告支持地址筛选、排序、打印及查看请求量、失败率、耗时、P95/P99、状态码和来源 IP。

导出不会修改采集设置或删除历史。仅能导出已采集且仍保留的数据；已有 Nginx/Caddy 日志来源只导出近期样本，报告会标明范围。当前筛选按整类地址选择，导出包含该类全部记录，统计与明细一致。

- **代理日志**：读取所选本机/Docker Nginx，或已开启 JSON 访问日志的本机 Docker Caddy。没有日志不等于没有流量。
- **后端请求**：打开「请求记录 → 接入后端」，从已发现的代理规则中选择后端，确认后开启。Python、Go、Java 等 HTTP 服务使用相同流程，无需逐个填写 API。保留原业务和外层 HTTPS，支持 HTTP、SSE/WebSocket。详见[网关说明](REQUEST_GATEWAY.zh-CN.md)。
- 网关请求自动保存到面板数据目录，默认查询最近 24 小时，可选 1 小时或 7 天，升级和面板重启保留。按接口类型汇总并分页，每类可展开最近 30 条明细；已有 Nginx/Caddy 日志来源仍只预览近期样本。
- 点击单条请求查看来源 IP、常用请求头、协议、上游地址和响应大小。网关自动升级托管日志格式；已有 Nginx 的旧日志可在高级设置点击「升级日志详情」。字段取决于采集来源，旧记录无法补采。代理声明的 IP 单独显示在请求头中。
- 单条详情还显示请求 ID、上游尝试状态和连接/等待响应头/传输耗时。网关沿用有效的 `X-Request-ID`，缺失或无效时自动生成并传给后端、返回给客户端；已有代理日志只读取已有字段，无法补造后端日志关联信息。
- 「状态 → 含慢请求」默认筛选耗时至少 1000 ms 的请求，可调整阈值。地址汇总保持该类的完整统计，明细仅展示符合阈值的最近请求；查找框支持路径、域名、来源 IP 和请求 ID。
- 记录方法、域名、路径、状态和耗时，不采集查询参数、认证头、Cookie 或请求体。历史最多保留 7 天，并受全局条数和容量限制，界面显示采集异常或单批超限；长连接结束后才有完整记录。详见[保留范围](REQUEST_GATEWAY.zh-CN.md#记录范围)。

网关接入会备份并修改所选代理规则，Caddy 重启可能短暂中断连接；这属于明确确认后的运维操作。停止记录恢复原网站访问路径，网关仍保留运行，后续维护需单独确认。

## 旧版本升级

部署页面、队列、脚本执行及仓库识别适配器已移除。旧部署 API（含手动部署、部署回滚和 WebHook）返回 HTTP `410 Gone`。

站点保存到 `sites.json`，旧 `projects.json` 只读提取站点，不被改写。监控状态写入 `monitoring-state.json`；原 `state.json` 保留，不加载其中的部署队列，启动或重启都不会自动恢复旧任务。

旧服务器上的业务文件、配置、脚本、服务、容器和持久数据全部保留。停止部署功能不等于停止业务，不会因本次转型清理或重建已有资源。后续业务发布由原维护流程负责，面板不再执行旧脚本。

升级前保留服务器快照和安装备份，复用原安装路径及环境文件。不要删除旧项目配置、队列状态或脚本来绕过升级检查。

## 排查与数据

资源告警默认启用：CPU、内存、根分区、inode、Swap、I/O 等待、每核负载及高占用下的内存持续增长。默认持续超限 60 秒才提醒，回落到较低阈值并稳定 30 秒确认恢复，缺失采样不会当作恢复。「告警与事件 → 提醒规则 → 服务器资源阈值」可调整阈值或关闭资源告警，性能历史仍持续采集。通知沿用原有渠道、静音、知晓与失败重试；没有配置通知渠道时仍在面板显示。

点击异常的「排查异常」，查看保存的资源统计、当时的进程现场和前后 5 分钟的其他异常/容器事件；可靠识别的服务或容器会关联日志来源。进程现场不会被当前进程列表替换，时间相近不代表因果，日志内容按需读取。部分资源异常保留触发时的简要现场，其他历史受各自保留期限限制。

异常中心不再展示 Prometheus 接入入口；已有启用的只读 `/metrics` 集成保持兼容，升级不会自动撤销已有密钥或改动外部监控配置。

「服务器状态 → 核心资源趋势 → 24 小时性能」查看持续采集的服务器历史，默认最近 24 小时，也可选 1 小时、7 天。每秒采集，在后台每 30 秒保存平均值、峰值及有效采样数；不需要一直打开网页。覆盖 CPU、内存、Swap、系统负载、根分区与 inode、网络吞吐和磁盘 I/O，重启面板后保留。

历史窗口默认自动更新，每 15 秒检查新保存的数据，曲线平滑过渡；已有展开现场、筛选和阅读位置保留。可取消「自动更新」暂停查看，也可手动刷新。网页切到后台或关闭窗口后暂停检查，服务器采集继续运行；导出的报告为导出时的固定快照。

在线预览和自动刷新使用压缩传输，进程明细在展开时读取，避免首次下载整批明细。首次加载遇到连接中断或超时会显示中文提示，自动更新开启时逐步重试；关闭窗口或暂停自动更新会停止重试。原历史数据和离线导出内容保留。

点击「导出报告」下载完整性能采样 CSV、指标汇总 CSV 和可离线打开的图表报告；也可单独下载采样 CSV。报告显示实际覆盖率和采集空档，不把缺失值算成 0。安装或升级后从当前时刻开始积累，过去的数据无法补回；无需等满 24 小时才能查看。停机、磁盘写入失败或强制终止可能丢失尚未保存的采样。历史数据库位于数据目录 `performance/server.sqlite3`，最多保留 7 天或 22000 组统计，同时受 128 MiB 总库容量限制（包含统计、现场摘要、压缩明细和索引）。写入前检查实际页占用，接近容量上限会提前轮换较早的性能记录，预留空间并复用数据库空闲页；不会删除或重建数据库文件。历史库可能保持 128 MiB 文件大小，空闲页会供后续采样复用，事务日志仍需额外磁盘空间。

写入失败时，资源观测和性能报告会显示错误；待写数据暂存于内存并自动重试，恢复后分批保存，不会把实时数据冒充持久历史。若服务器磁盘仍有空间、历史库恰好达到 128 MiB，更新到包含容量轮换修复的版本即可自动恢复后续写入，无需清空历史库。更新重启前尚未持久化的采样可能丢失，已保存且未超过保留限制的数据继续保留。

性能报告中的「进程现场」可展开查看当时的 CPU、内存、磁盘读写排名、PID、用户、父进程、线程数、状态、可执行文件和所属服务/容器；点击趋势中的时间点也可定位附近现场。进程每约 5 秒采集，每 30 秒保留压力最明显的一次现场，自动标注 CPU 突升、内存增加、高负载等排查线索。CPU 单核 100% 表示占满一个逻辑核，整机占比另列。相同时刻的高占用不是因果证明；短暂进程、采样之间的尖峰和权限不足可能遗漏，网络流量与磁盘空间增长不直接归因到某个进程。

导出 ZIP 另含 `scenes.csv`（现场索引）和 `processes.csv`（全部保留的进程现场）。离线 HTML 内嵌最近和高压力现场最多 240 组，网页预览可按需读取其他现场。进程明细压缩保存，最多 7 天或 32 MiB；达到明细预算会先淘汰较早现场，不影响总体统计。总体统计和现场还共同受上述总库容量限制。不会读取进程命令参数、环境变量或业务文件内容。

连接 SSH 后，点击终端工具栏「文件」即可浏览远程目录、查看权限和大小、上传下载、新建文件夹及编辑文本。桌面可拖动列表与预览间的分隔线；手机在列表和预览之间切换。

文本编辑最多 1 MiB，保存前预览差异、备份原文件并校验；版本已变化时拒绝覆盖。上传和下载每个文件最多 32 MiB，支持进度与取消；上传覆盖需确认并保留备份。失败或取消会保留远程备份和候选文件，不会自动重载业务配置。没有删除、移动或权限修改操作；符号链接及特殊文件仅展示。

远程服务器需要启用 SFTP，访问范围由连接账号权限决定；不会提权或执行 Shell 来绕过限制。文件管理沿用 SSH 登录、主机指纹和 HTTP 访问确认。

「服务器状态 → 更多性能指标」可查看 Swap、根分区 inode、磁盘读写与 I/O wait。容器的「资源历史」每 30 秒保存 CPU/内存，最多保留 7 天或 20 万条；容器重建按新 ID 单独记录。请求汇总展开后显示 P95/P99，使用所选时段内已保存的有效耗时，已有代理来源则按当前采集样本计算。

「服务器状态 → 面板维护」可检查 GitHub/Gitee 版本、创建完整备份、校验备份和恢复程序快照。更新会短暂重启面板，独立进程执行健康与运行版本检查，失败时尝试恢复操作前的程序。仅替换面板程序，当前配置、请求历史及业务文件保留；备份不自动删除。运行环境或数据兼容约定变化时，需使用 `install.sh` 更新，不在网页直接升级。

新增 Python 模块或维护脚本不再被误判为数据不兼容，网页更新按目标清单安装并在切换前检查；恢复程序时使用快照自己的文件清单，新增文件保留、不删除。依赖清单或 systemd 服务模板变化仍需安装器。新增路径若已有非面板文件，更新会在停止服务前拒绝覆盖；没有执行更新时明确提示「当前服务和程序未改动」。

若旧面板出现「更新涉及安装或数据兼容变化」，切换 GitHub/Gitee 不能修复旧更新器自身的判断。请在服务器执行以下一整行，先升级一次更新器；它从临时目录安装，沿用现有环境文件中的安装路径，不要求 `/opt/mini_deploy` 是 Git 仓库，也不重新配置 Docker、Nginx 或 HTTPS：

```bash
mini_deploy_update="$(mktemp -d /tmp/mini-deploy-update.XXXXXX)" && git clone --depth 1 --branch main https://github.com/jokerXueC/mini_deploy.git "$mini_deploy_update" && SETUP_NGINX=no SETUP_HTTPS=no SETUP_DOCKER=no bash "$mini_deploy_update/install.sh" && systemctl status mini-deploy-agent --no-pager -l
```

如果服务器无法访问 GitHub，将 `--branch main https://github.com/jokerXueC/mini_deploy.git` 换为 `--branch master https://gitee.com/XC1960/mini_deploy.git`。旧更新器会在运行新代码之前拒绝变化的发布清单，所以仅刷新网页或继续点击旧更新按钮无法安装本次修复。升级成功后，兼容的后续版本可继续使用网页更新。

安装器与后台写入共用维护锁，遇到占用会自动等待最多 60 秒。普通后台写入的读锁也会阻止安装器立即取得独占锁，不代表另一个安装任务一定在运行。超时则在升级前退出，并在系统提供 `lslocks` 时显示占锁进程；等待任务结束后重试即可。不要删除锁文件来绕过检查，以免更新与数据写入并发。

网页维护只支持 root + systemd 的标准 Linux 安装；本地演示禁用操作。完整备份的配置/数据库恢复需单独核对，不会通过「恢复程序」覆盖。断电、进程被强制终止或磁盘故障可能需要人工检查保留的备份；Linux 实机更新/恢复验收仍需完成。

默认安装使用：

```bash
systemctl status mini-deploy-agent --no-pager
journalctl -u mini-deploy-agent -n 100 --no-pager
curl -fsS http://127.0.0.1:6868/health
bash /opt/mini_deploy/scripts/doctor.sh
```

忘记密码时，在服务器运行 `python3 /opt/mini_deploy/agent.py admin set-password`，然后重启 Agent。只需撤销会话时使用 `admin reset-session` 后重启。自定义安装使用安装器打印的完整命令。

| 内容 | 默认位置 |
| --- | --- |
| 数据目录 | `/var/lib/mini-deploy-agent` |
| 站点配置 / 监控状态 | 数据目录中的 `sites.json` / `monitoring-state.json` |
| 保留的旧文件 | 数据目录中的 `projects.json` / `state.json` |
| 上传证书 / Nginx 元数据 | 数据目录中的 `certificates/` / `nginx.json` |
| 日志 | `/var/log/mini_deploy` |
| 安装备份 | `/var/backups/mini-deploy-agent` |

备份中的 `installation.tar.gz`、`manifest`、`complete` 必须整体保留。可用 `python3 /opt/mini_deploy/scripts/verify_backup.py <备份目录>` 做只读校验，但它不是恢复命令。手动备份使用安装器打印的完整命令；业务数据库、数据卷和外部代理配置需独立备份。

Docker 默认每小时清理创建超过 24 小时、无标签且没有任何容器引用的悬空镜像；有标签的镜像、运行中和已停止容器引用的镜像都会保留。可在环境配置中设置 `DEPLOY_DOCKER_AUTO_IMAGE_CLEANUP=false` 并重启面板关闭自动清理。镜像列表显示引用状态，“清理未使用镜像”需确认，会包含未引用的有标签镜像和刚下载的镜像，不清理容器、数据卷或服务器业务文件。

在告警中点击 **AI 诊断**，或打开服务器性能历史后点击 **AI 分析**，即可分析面板所在服务器，无需连接 SSH。先在“模型设置”保存兼容 OpenAI 或 Claude 的模型；HTTP 访问需确认本次登录授权。所选范围的证据、问题及按需读取的关联日志会发送给配置的模型服务，常见凭据会脱敏。诊断记录自动保存，可在诊断窗口查看历史并追问。诊断工具只读，不修改主机；执行处理方案需核对同一服务器并使用 SSH 的现有权限与审批。缺失或过期的数据不能补回，时间相关也不等于已确认原因。

其他 Docker 删除操作仅在明确选择并确认后执行：删除停止的容器会丢失其可写层，保留数据卷和宿主机挂载目录；镜像删除不是业务卸载。升级脚本本身不执行删除操作。

## 安全中心

页面集中展示最近 24 小时登录地区、IP 登录记录和当前临时封禁。面板登录立即保存，主机 SSH 日志约每 10 秒增量采集，页面约每 5 秒刷新。支持按来源和成功/失败筛选、分页、查看单条认证摘要；记录仍保存在数据目录 `security/history.sqlite3`，保留 30 天、最多 20000 条。历史库不会在升级时重建。

自动防护内置“统计窗口 → 失败阈值 → 临时封禁 → 到期解封”策略，不依赖 Fail2ban。默认开启：10 分钟内同一 IP 在同一登录来源失败 5 次，封禁该来源 1 小时。业务 HTTP 错误不计入。设置默认收起，保存时自动保留当前访问 IP，支持白名单、暂停防护和手动解封；手动解封后旧失败记录不会立即重复触发。现有 Fail2ban 及其他防火墙规则保持独立，不自动卸载或改写。

面板登录在应用内校验封禁状态。SSH 自动识别主机监听端口与认证日志，在 Linux 的 nftables 专属表 `inet mini_deploy_login_guard_v1` 中，仅阻止封禁 IP 到 SSH 端口的新连接，兼容 IPv4/IPv6。缺少 nftables、权限不足或无法可靠读取日志时会明确显示未生效，不自动猜测端口。没有清空系统防火墙、修改 sshd 或封禁 Docker 业务端口。规则应用为原子批次，封禁带内核超时；重启后按数据库剩余时长恢复。暂停或解封未能同步防火墙时保留原记录并报错。

地图底图随面板提供，无需外部地图服务。公网 IP 归属地在后台通过 HTTPS 查询 ipwho.is，仅发送 IP，不发送账号、日志内容或凭据；每分钟最多查询 2 个公网 IP，结果与失败状态缓存 24 小时。内网/保留地址不外发，无法定位不生成假坐标。地图仅展示最近 24 小时最多 500 个活跃 IP 的近似位置，常亮标记不代表设备实时位置。SSH 日志首次从最近 24 小时补采，旧记录不会单独触发自动封禁。

登录记录只使用直连来源或已明确受信任的本机代理头，不信任任意客户端传入的 X-Forwarded-For。经代理访问时可能只能看到代理地址；Docker 中的 SSH 服务不属于主机 SSH 防护范围。

## 基础防护开关

安全中心的“基础防护”默认关闭，点击后异步扫描本机与 Docker 网站入口，保留当前访问 IP 和已有管理连接。登录防护沿用现有设置并启用；关闭基础防护后恢复开启前的登录设置。操作期间页面持续显示进度，刷新或关闭页面不会取消已经提交的操作。

- 连接防护使用独立表 `inet mini_deploy_basic_guard_v1`，对检测到的 80/443 TCP 新建连接按来源限制为每秒 60 次、突发 120 次；包含 Docker DNAT 转发入口，兼容 IPv4/IPv6，不限制 UDP/QUIC，不是完整 DDoS 清洗。需要主机已有 nftables 和相应权限，缺失时显示未接入，不自动安装软件或接管其他防火墙。
- 对常见、可安全读取并修改的 Nginx HTTP 配置，在现有入口添加每来源 100 请求/秒、突发 200、100 个并发请求限制，超额返回 429。共享出口或 CDN 场景可能把多名用户视作同一来源，启用前应核对来源边界。有现成限流、真实 IP 配置、PROXY 协议、自定义启动参数或不可映射挂载时保留原配置并显示原因。标准 Caddy 不自带 HTTP 请求限流，本版仅提供可用的主机连接防护，不插入网关或安装插件。
- 配置原文与候选内容保存在权限受限的 `security/history.sqlite3` 操作记录中；写入前核对内容，保留文件 inode，校验和重载失败尝试恢复。业务更新改变文件时标记需核对，不自动覆盖。关闭时仅恢复未被外部修改的配置，存在冲突或恢复失败则明确显示部分完成，保留记录供后续恢复。数据库备份可能包含业务配置秘密，应按凭据保护。
- 下载带宽限速尚未启用，避免影响大文件、SSE 与 WebSocket；请求次数限制不能替代响应字节数和出口带宽限制。生效范围默认折叠，未接入的能力不会显示为已生效。每分钟检查规则与配置变化，主机重启后恢复已开启的专属连接规则。

异常中心的异常历史每页显示 5 条，筛选和翻页不改变保留记录的数量。
